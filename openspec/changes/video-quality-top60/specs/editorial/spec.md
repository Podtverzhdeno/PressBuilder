### Requirement M01 — Единый рациональный монтажный граф

> **M01-R01 (частичная реализация, не приёмка):** read-only snapshot P01/P05/P08/P09, frame-accurate 240000-tick timebase, SHA источников, CAS-предложение обрезки только для утверждённого P08, MCP/REST/Studio просмотр. Все новые изменения остаются `REVIEW_ONLY`, рендер и публикация не разрешены. Не реализованы PCM-level точность, применяемые edits/undo, P17/P18 интеграции, mixed-fps actual MP4 E2E, security signoff и canary. См. [docs/M01_RATIONAL_EDITGRAPH.md](../../../../../docs/M01_RATIONAL_EDITGRAPH.md).


- **Тип:** Системная; **оценки Q/E/F/C/S/L:** 10/10/7/8/10/10; **зависимости:** P05,P08,P09,P17,P24; **статус:** PROPOSED.
- **Проблема и продуктовая ценность:** Клипы, звук, титры и переходы сегодня рискуют считать длительности разными часами; отсюда рассинхрон, дрейф и недетерминированный повторный рендер.
- **Алгоритм / декомпозиция:** Ввести typed EditGraph v1: проект, треки, клипы, trims, transition handles, rational PTS и provenance SHA. Узлы имеют стабильные IDs; solver переводит P09 слова, P17 стыки и P18 ключи в один timebase. Хранить неизменяемые ревизии графа отдельно от deck.json; публикация только через P05.
- **Контракт и границы доверия:** GET graph, POST proposal(expected_revision,source_fingerprints), diff; команды trim/split/move/crossfade типизированы, AST-валидация запрещает отрицательную длину и пустые source intervals.
- **Проверяемое поведение / DoD:** Шесть сцен со смешанными 24 и 30000/1001 fps должны собираться без накопленного временного дрейфа; 1000 операций undo/redo восстанавливают побайтово идентичный граф; stale CAS и чужие сцены отклоняются.
- **Негативные сценарии и trade-off:** Миграция старой структуры, сохранение кросс-кадровых аудиосэмплов, тесты на переполнение BigInt и сохранение принятого P08/P05.
- **План внедрения:** (1) versioned schema + threat model; (2) pure planner + deterministic fixtures; (3) P06-scoped REST/MCP с CAS и Studio read-only A/B; (4) реальные MP4/PCM + независимое ревью; (5) canary и выключенный по умолчанию feature flag. Ни один автоматический кандидат не меняет P08 approved или P05 release pointer без отдельной подписанной операции.

### Requirement M02 — Независимый режиссёрский совет A/B

- **Тип:** Системная; **оценки Q/E/F/C/S/L:** 9/9/7/7/8/9; **зависимости:** P07,P10,P16,P23; **статус:** PROPOSED.
- **Проблема и продуктовая ценность:** Один генератор видеоряда часто закрепляет собственные ошибки; одно и то же качество оценивается им же без слепого сравнения.
- **Алгоритм / декомпозиция:** Для каждого черновика два независимых critic-профиля предлагают timecoded замечания по смыслу, ритму, типографике и звуку. Агрегатор убирает дубли, фиксирует разногласия и показывает автору A/B рядом с исходными MP4; решение человека отделено от самооценки модели.
- **Контракт и границы доверия:** critique_v1: baseline_sha, candidate_sha, model_version, time_range, finding_type, severity, evidence_frame_sha; reviewer_id и решение хранятся отдельно.
- **Проверяемое поведение / DoD:** На 20 размеченных дефектах измерить recall/false-positive и время исправления; blind A/B не должен раскрывать вариант агенту-судье; false verdict запрещён без кадра/времени.
- **Негативные сценарии и trade-off:** Высокая модельная стоимость и bias критиков; запрещено самоподписание, raw транскрипт без consent не отправлять наружу.
- **План внедрения:** (1) versioned schema + threat model; (2) pure planner + deterministic fixtures; (3) P06-scoped REST/MCP с CAS и Studio read-only A/B; (4) реальные MP4/PCM + независимое ревью; (5) canary и выключенный по умолчанию feature flag. ### Requirement M03 — Монтаж по утверждённым фразам

- **Тип:** Системная; **оценки Q/E/F/C/S/L:** 10/9/8/8/9/9; **зависимости:** P09,P10,P15,P16,P24; **статус:** PROPOSED.
- **Проблема и продуктовая ценность:** Подрезка вручную по смыслу медленна, а произвольный LLM-рефакторинг может поменять факты и смысл речи.
- **Алгоритм / декомпозиция:** Создать paper edit: каждое утверждение сценария связывается с word alignment, cue_id, source_mp4 интервалом и лицензией. Редактор выделяет точные фразы; solver собирает кандидатную историю с hard constraints на смысл, паузы и обязательные факты. Отсутствующие слова не сочиняет.
- **Контракт и границы доверия:** SelectedSpans_v1 содержит word IDs, rational PTS, claim_id, source SHA, mandatory_keep и rejected_reason; output graph не меняет первоначальный исходник.
- **Проверяемое поведение / DoD:** Три версии 30/45/60 секунд сохраняют 100% mandatory claims, 0 склеек посреди защищённого слова; revert возвращает исходный script/MP4.
- **Негативные сценарии и trade-off:** ASR может ошибаться; выделения непроверенных слов блокируют публикацию; человеческое утверждение смысла обязательно.
- **План внедрения:** (1) versioned schema + threat model; (2) pure planner + deterministic fixtures; (3) P06-scoped REST/MCP с CAS и Studio read-only A/B; (4) реальные MP4/PCM + независимое ревью; (5) canary и выключенный по умолчанию feature flag. ### Requirement M04 — Карта внимания, ритма и смысловых кульминаций

- **Тип:** Системная; **оценки Q/E/F/C/S/L:** 9/9/8/9/8/9; **зависимости:** P15,P16,P23; **статус:** PROPOSED.
- **Проблема и продуктовая ценность:** Ролик выглядит механической нарезкой с одинаковыми интервалами, хотя смысловая напряжённость меняется.
- **Алгоритм / декомпозиция:** Строить по временным фрагментам signal map: речь/паузы/акценты/длительность кадра/новизна сцены; по одобренной режиссёрской арке предлагать интервалы напряжения, ускорения и передышки. Optimizer ограничивает частоту склеек и ценность кадра, а не гонится за retention любой ценой.
- **Контракт и границы доверия:** NarrativeEnergy_v1: approved_story_revision, 0..1 intensity, min/max shot frames, highlighted cue, proposal_only; без прямой записи timeline.
- **Проверяемое поведение / DoD:** На 6-сценном ролике кандидат обязан содержать минимум одну мотивированную смену темпа, не обрезая речь; измерить субъективную слепую оценку и долю ручных исправлений.
- **Негативные сценарии и trade-off:** Метрика удержания без реальных просмотров — гипотеза; не подменять художественное решение псевдонаучным score.

### Requirement M05 — Транзакционный ripple edit и групповой undo

- **Тип:** Атомарная; **оценки Q/E/F/C/S/L:** 9/10/9/9/10/10; **зависимости:** P06,P08,P24; **статус:** PROPOSED.
- **Проблема и продуктовая ценность:** Сдвиг одного клипа вручную может увести озвучку, титры и эффекты, а несколько агентов способны перезаписать соседние дорожки.
- **Алгоритм / декомпозиция:** EditTransaction объединяет редактирование сегмента, связанных титров и звука; preflight рассчитывает все downstream смещения в кадрах и явные locked anchors. Atomic compare-and-swap + reversible journal commit/rollback. Проектные, дорожечные и сценные роли применяются до commit.
- **Контракт и границы доверия:** POST edit/preview returns delta graph, affected_ids, conflict set; POST edit/commit requires actor, exact revision, lease, idempotency.
- **Проверяемое поведение / DoD:** При инъекции ошибки в 1 из 7 затронутых объектов не меняется ничего; 50 циклов edit/undo дают SHA-равенство исходника; конкурентное редактирование выдаёт конфликт, не last-write-wins.
- **Негативные сценарии и trade-off:** Сложное пересечение P06-scene leases; не пытаться атомарно перезаписывать обычный deck.json без миграции.
- **План внедрения:** (1) versioned schema + threat model; (2) pure planner + deterministic fixtures; (3) P06-scoped REST/MCP с CAS и Studio read-only A/B; (4) реальные MP4/PCM + независимое ревью; (5) canary и выключенный по умолчанию feature flag.
