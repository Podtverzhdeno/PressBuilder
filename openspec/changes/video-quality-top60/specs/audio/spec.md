# OpenSpec Top-60 / B. Аудио, озвучка, речевой ритм

> PROPOSED; voice privacy by design. Лицензированные исходники, локальные PCM и раздельные версии — обязательные границы. Итоговый рейтинг в `docs/TOP60_MONTAGE_RANKING.md`.

### Requirement M11 — Достоверная покомпонентная синхронизация слов

- **Тип:** Атомарная; **оценки Q/E/F/C/S/L:** 10/10/8/8/9/10; **зависимости:** P09,P15,P19; **статус:** PROPOSED.
- **Проблема и ценность:** Ритм и титры нельзя выстраивать по approximate секундным cue — граница слова, вдох и согласные оказываются вне кадра.
- **Технический механизм:** Собрать опциональный локальный ASR + VAD + forced-alignment, с сохранением user-approved текста как истины. Каждый word получает начало/конец PCM sample и уверенность; номера, аббревиатуры и кириллица требуют лексикон исключений. Редактор показывает нераспознанные фразы как REVIEW.
- **Данные, API и безопасность:** WordMap v1: speech_sha, language, provider/model SHA, word text/source cue, sample_start/end, confidence_band, manual_override_revision; вся обработка приватная, no raw transcript logs.
- **Проверяемые критерии:** 20 русско-английских речевых fixtures с ручной разметкой: медиана абсолютного отклонения границы слова ≤40 мс как целевой порог после калибровки; неизвестное слово никогда не получает фиктивный timestamp.
- **Риски и отказ:** WhisperX/модели могут неточно выравнивать числа и перекрывающиеся голоса; GPU по желанию, fallback manual, модель/лицензию фиксировать.
- **Пошаговый SDD:** contract/source SHA → измеримый pure PCM анализ → доступ к отчёту через P06/Studio A/B → bounded background FFmpeg или локальная модель → Docker test на лицензированных данных → независимое прослушивание и canary. Нельзя менять approved stems или историю без reviewer-approved CAS; целевые числа подлежат калибровке, не являются фактическими достижениями.

### Requirement M12 — Деликатная очистка голоса и двойной A/B-спектр

- **Тип:** Атомарная; **оценки Q/E/F/C/S/L:** 9/10/8/7/8/9; **зависимости:** P09,P19,P23; **статус:** PROPOSED.
- **Проблема и ценность:** Шипение, комнатный гул и резкие согласные отвлекают; агрессивный denoise превращает речь в роботизированную.
- **Технический механизм:** Двухступенчатая обработка: детектор шумового профиля с sample-locked regions, затем configurable low/high-pass, de-esser, spectral gating без замещения фонем. Непереписываемый исходный голос, нормированный по loudness A/B после каждой операции.
- **Данные, API и безопасность:** AudioRepair_v1: source PCM sha, window profile, denoise strength bound, applied filters enum, acoustic risk flags; рендер через whitelisted FFmpeg argv.
- **Проверяемые критерии:** Сравнить 10 clean/noisy клипов до и после, снижения фонового шума добиться без увеличения частоты ошибок распознавания по human transcript; clipping 0, p95 задержки в пределах бюджета.
- **Риски и отказ:** Переочистка уничтожает тембр, особенно мягкие звуки; при низком SNR нужен явный manual-only, не «улучшить любой ценой».
- **Пошаговый SDD:** contract/source SHA → измеримый pure PCM анализ → доступ к отчёту через P06/Studio A/B → bounded background FFmpeg или локальная модель → Docker test на лицензированных данных → независимое прослушивание и canary. Нельзя менять approved stems или историю без reviewer-approved CAS; целевые числа подлежат калибровке, не являются фактическими достижениями.

### Requirement M13 — Финальное микширование с EBU-профилями и автодакингом

- **Тип:** Системная; **оценки Q/E/F/C/S/L:** 10/10/9/8/9/9; **зависимости:** P09,P19,P23; **статус:** PROPOSED.
- **Проблема и ценность:** Непостоянная громкость речи/музыки и перегрузка master делают ролик непрофессиональным на телефоне и в наушниках.
- **Технический механизм:** Вести раздельные voice/music/sfx stems; от VAD строить bounded sidechain ducking с attack/release и защищёнными паузами. Выполнить двухпроходное loudnorm и true-peak limiter с explicit preset (broadcast, web, custom), без одного «магического» LUFS для всех платформ.
- **Данные, API и безопасность:** MixPlan_v1: approved PCM SHA каждого стема, gain automation, per-role target, output channel layout, measured I/LRA/TP, exact FFmpeg settings.
- **Проверяемые критерии:** На 12 сценариях перехода голос/музыка voice не теряется, master достигает выбранного preset в ±0.5 LU как проектная цель; пик не выше указанного ceiling; независимое прослушивание A/B обязательно.
- **Риски и отказ:** Два прохода затратны; -23 LUFS относится к EBU R128 broadcast, а online preset задаётся отдельно, не выдавать платформенный target за универсальный.
- **Пошаговый SDD:** contract/source SHA → измеримый pure PCM анализ → доступ к отчёту через P06/Studio A/B → bounded background FFmpeg или локальная модель → Docker test на лицензированных данных → независимое прослушивание и canary. Нельзя менять approved stems или историю без reviewer-approved CAS; целевые числа подлежат калибровке, не являются фактическими достижениями.

### Requirement M14 — Просодический ритм вместо резки по BPM

- **Тип:** Атомарная; **оценки Q/E/F/C/S/L:** 9/9/7/8/9/8; **зависимости:** P09,P15; **статус:** PROPOSED.
- **Проблема и ценность:** Точная нарезка по музыкальному пульсу режет речь, драматические паузы и интонационные акценты.
- **Технический механизм:** Из PCM получать фразы, локальные паузы, изменение интенсивности и pitch contours; менять веса cut candidates для повествования по ударению и смене мысли. Выводить три объяснимых альтернативы, не автоматический монтаж.
- **Данные, API и безопасность:** ProsodyMarkers_v1: speaker-free feature frames, cue anchors, word mask, phrase stress, provenance and confidence; ни сырое аудио, ни inferred эмоции не отправлять в external service.
- **Проверяемые критерии:** На наборе интонационных фраз ни один cut не пересекает protected words; экспертная оценка выбранного местоположения превосходит baseline BPM-cut на слепом тесте либо не выводится улучшение.
- **Риски и отказ:** Нельзя утверждать распознавание эмоций или намерений; интонационные оценки чувствительны к голосу/языку.
- **Пошаговый SDD:** contract/source SHA → измеримый pure PCM анализ → доступ к отчёту через P06/Studio A/B → bounded background FFmpeg или локальная модель → Docker test на лицензированных данных → независимое прослушивание и canary. ### Requirement M15 — Непрерывный разговор через реальные аудиохэндлы J/L

- **Тип:** Атомарная; **оценки Q/E/F/C/S/L:** 10/9/8/8/9/8; **зависимости:** P08,P17,P19; **статус:** PROPOSED.
- **Проблема и ценность:** Даже визуально идеальный hard cut звучит рвано, если реплика начинается ровно на новом кадре.
- **Технический механизм:** Сервер вычисляет фактические pre/post handle sample ranges из двух immutable P08 artifacts, затем строит отдельно video cut и audio in/out PTS. Визуальный A/B спектр, линейная или equal-power кросс-огибающая с заданными границами; никогда не дополнять недостающий handle тишиной.
- **Данные, API и безопасность:** AudioBoundary_v1: left/right version SHA, stream timebase, decoded sample positions, crossfade curve, expected approval revision.
- **Проверяемые критерии:** Аудио до/после стыка не теряет первых согласных, ни один sample не читается за исходным потоком; при invalid handle и stale revision fail closed, output approval остается прежним.
- **Риски и отказ:** Для некоторых клипов хвосты не содержатся в P08 MP4; тогда требуется исходный PCM stem либо функция недоступна.
- **Пошаговый SDD:** contract/source SHA → измеримый pure PCM анализ → доступ к отчёту через P06/Studio A/B → bounded background FFmpeg или локальная модель → Docker test на лицензированных данных → независимое прослушивание и canary. ### Requirement M16 — Семантические звуковые акценты по лицензированным ассетам

- **Тип:** Атомарная; **оценки Q/E/F/C/S/L:** 8/8/8/8/9/7; **зависимости:** P19,P22; **статус:** PROPOSED.
- **Проблема и ценность:** UI-анимация выглядит дешёво без точных звуковых подтверждений, но случайные whoosh перегружают ролик.
- **Технический механизм:** Каталог отдельно утверждённых SFX (тонкие whoosh, click, reveal, low-impact) со спектральными envelope и лицензией. Триггер связан с точным событием 3D keyframe/clip, динамический limiter и budget максимального числа SFX на 10 сек.
- **Данные, API и безопасность:** SfxCue v1: asset_id, license_ref, event_id, samples_offset, gain_db, max_events, source_sha, dry-run preview.
- **Проверяемые критерии:** На 6 сценах три разных типа движения получают правдоподобный звук без рассинхрона (>1 frame), а «тихие» сцены сохраняют пустоту; отсутствующая лицензия блокирует микс.
- **Риски и отказ:** Риск звукового клише и усталости; не генерировать SFX автоматически без авторского согласования.

### Requirement M17 — Умная работа с паузами и вдохами

- **Тип:** Атомарная; **оценки Q/E/F/C/S/L:** 9/10/9/9/9/8; **зависимости:** P09,P15,P19; **статус:** PROPOSED.
- **Проблема и ценность:** Механическое вырезание тишины превращает речь в нервную скороговорку и удаляет выразительные вдохи.
- **Технический механизм:** На VAD + energy envelope различать длинную пустую тишину, дыхание, речевой зазор и музыкальную паузу. Предлагать trim с min/max breath preservation и оригинальным PCM provenance; интерактивно слушать три варианта.
- **Данные, API и безопасность:** SilenceEdit_v1: segments, category, confidence, protected_spans, offsets, per-speaker policy и reason.
- **Проверяемые критерии:** На размеченных 30 паузах 0 защитных вдохов/смысловых пауз удалены в automatic-safe профиле; обратимый edit не трогает произношение и исходную версию.
- **Риски и отказ:** VAD не понимает драматургию сам; classifier результат REVIEW, не уничтожает дыхание ради субъективного темпа.
- **Пошаговый SDD:** contract/source SHA → измеримый pure PCM анализ → доступ к отчёту через P06/Studio A/B → bounded background FFmpeg или локальная модель → Docker test на лицензированных данных → независимое прослушивание и canary. ### Requirement M18 — Контроль дрейфа аудио/видео вплоть до sample

- **Тип:** Системная; **оценки Q/E/F/C/S/L:** 10/9/8/8/10/10; **зависимости:** P05,P09,P17,P19; **статус:** PROPOSED.
- **Проблема и ценность:** В длинных сборках float FPS и resampling дают накопленный lip-sync и титровый drift.
- **Технический механизм:** Ввести rational mapping PTS_video↔PTS_audio; resample только по необходимому timestamp и журналировать измеренные sample drops/dupes. Проверять asset/container timebase ffprobe до замены версии; тестировать mixed 44.1k/48k и 30000/1001.
- **Данные, API и безопасность:** SyncReport_v1: source/audio stream timebase, frame-to-sample mapping, phase, measured max_absolute_drift, violation_ranges, hash.
- **Проверяемые критерии:** После последовательной сборки 10 клипов длительностью 5 минут на тестовом наборе max sync drift ≤1 output frame, отсутствие внезапных недокументированных сдвигов и выпадений речи.
- **Риски и отказ:** Ограничения исходного VFR и произвольного time stretch; политика отказа/нормализации зафиксирована и проверяется отдельно.
- **Пошаговый SDD:** contract/source SHA → измеримый pure PCM анализ → доступ к отчёту через P06/Studio A/B → bounded background FFmpeg или локальная модель → Docker test на лицензированных данных → независимое прослушивание и canary. ### Requirement M19 — Шины и stems как настоящий монтажный микшер

- **Тип:** Системная; **оценки Q/E/F/C/S/L:** 8/8/8/8/8/8; **зависимости:** P19,P24; **статус:** PROPOSED.
- **Проблема и ценность:** Сведение аудио в один поток не позволяет отдельно корректировать голос, музыку, окружение и использовать микс повторно.
- **Технический механизм:** Сделать 4 шины voice/music/sfx/ambience с собственными meters, mute/solo, send/sidechain и автоматизацией gain в sample domain. Микс компилируется в whitelisted фильтры и immutable stems, Studio отображает peak/LUFS каждого.
- **Данные, API и безопасность:** MixBuses_v1: track types, approved asset hashes, gain knots, routing graph без циклов, output master and isolated stems.
- **Проверяемые критерии:** Изолированная перестройка music не меняет voice stem SHA; 0 циклов аудиографа; snapshots и loudness preflight тестируются на PCM.
- **Риски и отказ:** Поддержка каналов >stereo отложена; DSP может стать CPU bottleneck, нужен лимит числа stems/эффектов.
- **Пошаговый SDD:** contract/source SHA → измеримый pure PCM анализ → доступ к отчёту через P06/Studio A/B → bounded background FFmpeg или локальная модель → Docker test на лицензированных данных → независимое прослушивание и canary. ### Requirement M20 — Произношение имён и терминов в озвучке

- **Тип:** Атомарная; **оценки Q/E/F/C/S/L:** 8/9/8/8/9/8; **зависимости:** P09,P10,P23; **статус:** PROPOSED.
- **Проблема и ценность:** Технический ролик проигрывает по качеству из-за неверных ударений, чисел, аббревиатур и английских названий.
- **Технический механизм:** Лексикон approved spellings + фонетических форм для TTS/ASR; сверять распознанные слова, script tokens и manual notes. Помечать только вероятные ошибки с timestamp, при наличии иных языков проверять токен по альтернативному lexicon.
- **Данные, API и безопасность:** PronunciationQA v1: glossary revision, token IDs, expected_text, recognized_text, audio span, confidence, reviewer decision.
- **Проверяемые критерии:** На 20 специальных терминах фиксировать ошибки без замены оригинальной записи; 0 автоматических замен терминов, false-positive отдельно измерить.
- **Риски и отказ:** Нужны языковые модели для RU/EN, ударения неоднозначны; автоматическая фонетика — подсказка, не доказательство ошибки.
- **Пошаговый SDD:** contract/source SHA → измеримый pure PCM анализ → доступ к отчёту через P06/Studio A/B → bounded background FFmpeg или локальная модель → Docker test на лицензированных данных → независимое прослушивание и canary.
