# 3D Scene SDK (P01) — MCP quickstart

**Статус:** работающий базовый `declarative Scene3D v1`. Поддерживает объёмную геометрию, перспективу, вращение и камеру без исходного TypeScript в чате. **Не является** пока загрузчиком glTF/GLB или универсальной заменой Blender/Three.js.

## С чего начинает внешний агент

1. `list_decks` — найти ID проекта, если неизвестен.
2. `get_project_context({id,slide_id})` — прочитать проектный README, сценовое ТЗ и чекпоинты.
3. `get_scene_3d({id,slide_id})` — узнать текущую ревизию и композицию (`spec=null` если ещё не создана).
4. `set_scene_3d({id,slide_id,expected_revision,spec})` — сохранить готовую композицию в **свою** сцену.
5. Проверить сцену в веб-редакторе (`get_editor_link`). После развёртывания облачного рендера `render_video` создаст общий MP4; раздельный рендер слайдов — задача P02.
6. Успешно проверенные этапы отмечать через `set_scene_checkpoint` с доказательствами.

## Пример spec для двух вращающихся 3D-объектов

```json
{
  "version": 1,
  "camera": {
    "cx": 1090,
    "cy": 500,
    "size": 245,
    "dist": 9.5,
    "yaw": -0.45,
    "pitch": 0.25,
    "yaw_speed": 0.45,
    "pitch_speed": 0.03,
    "zoom_speed": 0.02
  },
  "objects": [
    {
      "id": "core",
      "mesh": "icosa",
      "color": "#42d4ff",
      "edge_color": "#c6f5ff",
      "wire": true,
      "pos": [0, 0, 0],
      "scale": 2,
      "rotation": [0, 0, 0],
      "spin": [0.15, 0.8, 0.12],
      "start": 0,
      "fade": 0.5
    },
    {
      "id": "satellite",
      "mesh": "octa",
      "color": "#ffc06b",
      "pos": [2.3, 0.3, -1],
      "scale": 0.7,
      "rotation": [0, 0, 0],
      "spin": [0.1, -1.2, 0],
      "start": 0.7,
      "fade": 0.5
    }
  ]
}
```

`set_scene_3d` принимает этот `spec` плюс `id`, `slide_id` и `expected_revision`. Не нужно отправлять README, другие слайды или `deck.json`.

## Контракт

- Координаты модели — 3D `[x,y,z]`; экранные `cx/cy` — система 1920×1080; `size` — масштаб проекции в пикселях на мировую единицу.
- Скорости `spin` и `yaw_speed` — в радианах в секунду. Кадр при времени `t` не зависит от других кадров и воспроизводится детерминированно.
- Поддерживаемые меши: `cube`, `pyramid`, `octa`, `icosa`, `hexPrism`, `cylinder`.
- Лимиты: 1–18 объектов; scale 0.02–5; pos ±8; yaw speed ±2 рад/с; цвет только `#RRGGBB`; остальные числа также ограничены. Не поддерживаются произвольные скрипты, HTML или внешние URL моделей.
- Сцена пишется отдельным JSON: локально `src/decks/<id>/.scene3d/<slide_id>.json`, в Railway `/data/decks/<id>/.scene3d/<slide_id>.json`. Файлы из GitHub используются как шаблоны и не переписываются облачным агентом.
- REST: `GET /api/decks/:id/scene3d` для всех заполненных сцен; `GET /api/decks/:id/scene3d/:slide_id`; `PUT /api/decks/:id/scene3d/:slide_id` с `{spec,expected_revision}`.
- При конкурентной правке возвращается HTTP 409. Агент обязан заново прочитать ревизию.
- Если у того же слайда есть статическая кодовая сцена, опубликованный через MCP data-only Scene3D **имеет приоритет** только для него. Удаление / переключение источника пока не реализовано, это отдельный UX-пункт.
- Локальный Vite-редактор слушает событие `pb:scenes3d` и обновляет сцену без потери текущего `deck.json`. Облачный редактор загружает JSON при открытии ролика.

## Проверки и честные ограничения

Тест `tests/cloud-scene3d.test.mjs` подтверждает публикацию через MCP, чтение REST, ревизии и отказ при неправильном mesh, значениях, несуществующей сцене. `npm run build` подтверждает компиляцию SDK.

**Пока не подтверждено:** полноценный GLB/GLTF pipeline, отдельные анимированные камеры/keyframes, текстуры, высокополигональная геометрия, отдельный `render_scene`, независимое визуальное сравнение MP4 на Railway. Это запланировано в P01.5–P02.

### Контрольный кейс

Создать 2-слайдовый проект, залить scene3d только в `s01`; проверить, что `s02` не изменился и в `deck.json` нет изменений, а в live-редакторе `s01` показывает вращающиеся объекты. Полную production-приёмку делать только после настоящего MP4.
