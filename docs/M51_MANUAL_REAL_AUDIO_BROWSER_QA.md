# M51-R05 — запуск анализа звука MP4 из QC-кокпита

**Статус:** Draft PR поверх M58-R23 (#57). Флаг `PB_REAL_AUDIO_AUDIT`
по умолчанию выключен; деплоя, merge и публикации нет.

## Поведение интерфейса

Когда текущий P05 master уже подтверждён по SHA и аудиоочередь доступна,
QC-кокпит показывает состояние реального аудиоанализа. Для состояний
`NOT_STARTED`, `FAILED` и `STALE` предлагается явная кнопка:

**«Проверить звук текущего MP4»**

Это отдельный POST в `/api/decks/:id/audio-audit`. Запрос содержит
строго `release_id` и `release_sha256` из только что прочитанного
QC-кокпита. Сервер проверяет оба значения по актуальному master —
если выпуск сменился, результат **409** и никаких задач не создаётся.
Полученный job дополнительно проверяется по проекту, ID/SHA и
`publication_allowed:false` перед отображением.

Никакой анализ не запускается автоматически при открытии окна,
обновлении страницы, просмотре MP4 или изменении фильтров. Результат
после запуска можно получить нажатием уже существующей кнопки
«Обновить по текущему выпуску». Экспериментальные синтетические
выводы M58 остаются отделены от реального AAC.

Ошибки и статусы очереди не подтверждают качество. Нажатие кнопки
не принимает художественное решение, не проверяет права и не
создаёт P07 отметку `VERIFIED`. Дефекты звука содержат приблизительные
PCM-секунды, а не подтверждённые A/V PTS.

## Доказательство через Chromium, не только unit-тесты

`tests/cloud-qc-audio-browser.test.mjs` запускает **настоящий локальный
HTTP-сервер и Chromium через CDP**, с Basic Auth, и:

1. Создаёт тестовый deck через авторизованный MCP.
2. Генерирует настоящие H.264/AAC MP4 с инверсией правого канала,
   записывает корректный P05 master manifest/sha256.
3. Загружает редактор, выбирает проект и открывает QC-кокпит
   действительным пользовательским нажатием.
4. Проверяет видимость модального окна, кнопки ручного запуска,
   предупреждения, границы окна в 1280px viewport.
5. Нажимает кнопку в браузере, получает завершённый SHA-pinned receipt
   из реального FFmpeg-worker, обновляет модальное окно.
6. Проверяет реальные DOM-замечания об antiphase, кнопки перехода,
   предупреждение о неточности времени PCM и отсутствие разрешения
   на публикацию.
7. Захватывает **PNG через Chromium Page.captureScreenshot**,
   проверяет PNG-signature, размер в пикселях и непустой объём.

Тест не предполагает, что отдельный скриншот глазами просмотрен
дизайнером. В текущем CI screenshot не сохраняется как артефакт
для ручного approval; для production нужна отдельная визуальная
приёмка человеком и проверка на разных разрешениях.

В обычном Cloud CI без Chromium и FFmpeg браузерный тест ожидаемо
SKIP, в Docker image CI с ними должен **выполняться полностью**.

## Границы безопасности

- Существующая Basic Auth и cross-origin write защита сохранены.
- `get_qc_cockpit` через MCP остаётся read-only; scene-scoped
  пользователи не видят полных реальных аудиоотчётов.
- Задания сериализуются с FFmpeg/Chromium через общий governor.
- Загрузки GET не создают задач, POST требует явного действия.
- Выпуски и SHA сверяются перед каждой попыткой анализа.
- `publication_allowed:false` остаётся неизменным.
- Не включать `PB_REAL_AUDIO_AUDIT` на Railway без независимого
  security review, управления ресурсами и человеческого QA.
