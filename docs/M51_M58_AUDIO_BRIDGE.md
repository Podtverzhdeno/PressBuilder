# M51-R03 — безопасный мост M58 → QC-кокпит (только лабораторные аудиоданные)

**Статус: экспериментальный read-only API; не готов к реальному пользовательскому видео.**
Это расширение поверх M51-R02 (PR #52), отдельное от M58-R19 (PR #51).
Никаких новых прав на монтаж, ревью, публикацию или раскатку не возникает.

## Реализовано

`server/m58-qc-bridge.mjs` проецирует только **контролируемый**
M58-R19 stereo PCM отчёт на временную шкалу *того же* неизменяемого P05 master,
когда соблюдены **все** условия:

1. Сервер уже проверил текущий P05 релиз через `assembly.current(project)`.
2. `release_id`, SHA master MP4, последовательность **всех шести** SHA исходных
   сцен, 3-секундные отрезки и переходы 300 ms совпадают с M58-кейсом.
3. Отчёт имеет известную структуру лабораторного теста, семь 300 ms окон
   на сцену; локальные причины ошибок, агрегатные причины и 17.1s PCM
   длительность согласованы. Нельзя выбирать отдельные «зелёные» окна.
4. Отдельный **серверный** `verifyM58Report({release,report,candidate})`
   подтвердил исходное происхождение *и реальные байты*. Значение
   `report.status: ...VERIFIED` от самого отчёта не является доказательством.
   Отсутствие verifier/loader означает `NOT_CONNECTED`, расхождение — `REJECTED`.

Возвращаются только `SYNTHETIC_REVIEW_ONLY` замечания с указанием сцены,
начала PCM окна и отдельной человеческой рекомендации. Временная позиция
звука — ориентировочная для `video.currentTime`, **не точный video PTS**.
Проверка P05/P07 остаётся самостоятельной; новые лабораторные замечания
**не** подмешиваются в её счётчики, verified status и review disposition.
Версия `qc-cockpit-v1` получает только необязательное поле
`m58_audio_review`, а не новый авторизующий API.

В клиенте есть отдельный блок «Звук · M58 (только контрольный тест)»
для состояний нет источника / источник отклонён / проверенное лабораторное
соответствие. P06-scoped MCP-читатель не получает лабораторный отчёт всего
проекта: для scene-scoped запроса **loader вообще не вызывается**, а поле
`m58_audio_review` отсутствует в ответе.

## Что **не** сделано

Никакой M58 лабораторный loader/verifier **не подключён к production
`server/cloud.mjs`**. Живой QC-кокпит по умолчанию показывает
`NOT_CONNECTED`. Нельзя взять `tools/check-p05-known-voice-music.mjs` и
считать его вывод независимым подтверждением продакшен MP4: его сцены
синтетические, звук/голос задан контрольными тонами, а `M58` не является
отдельным доверенным issuer. `verifyM58Report:()=>true` допустим
исключительно в тестах верификации проекции, **не** на сервере.

Для полноценной интеграции отдельно нужны: авторизованный серверный
эмиттер M58-отчётов, server-owned подписанные receipts, проверка SHA
байтов источников и итогового master, привязка к реальному (не синтетическому)
аудиопрофилю, достоверный аудио/video PTS, персистентность, rollback и
независимый reviewer. Флаг публикации по-прежнему всегда `false`.

## Проверка

```bash
node --test tests/cloud-qc-m58-bridge.test.mjs tests/cloud-qc-cockpit.test.mjs tests/cloud-qc-cockpit-wire.test.mjs tests/cloud-qc-cockpit-triage.test.mjs
npm run typecheck
npm run build
```

Тестовый `verifyM58Report` подтверждает только согласованность фикстуры,
**не** независимую криптографическую аттестацию. Негативные тесты: другой
master/source SHA, не тот переход, подделанные окна, нестыковка агрегатных
issues, отсутствие/отказ verifier, P06 scope, отсутствие publish authority.

Релизная приёмка M51/M58 по-прежнему открыта.
